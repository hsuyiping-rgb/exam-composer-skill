## 適用對象與定位

- 使用者：新北市中和區光復國小校長，技能的實際使用對象是校內命題教師。
- 定位：**生成端**。負責從設定範圍、下載教材、生成試題與雙向細目表，到篩選替換與歸檔。
- 分工：審查端（登入 esa.ntpc.edu.tw 讀取 108~114 學年度歷屆考卷、比對查重、輸出審查報告）由 `esa-exam-review` 負責（位於 `~/.codex/skills/esa-exam-review` 與 Claude Code 外掛 `anthropic-skills:esa-exam-review`）。兩者是**管線關係**：本技能生成草稿 → 送 esa-exam-review 查重 → 定稿。**不要把查重邏輯重做一份。**
- 專案目錄：`G:\我的雲端硬碟\AI作品\定期考察命題技能`（GitHub：hsuyiping-rgb/exam-composer-skill）。

## 絕對原則（最高優先，蓋過任何效率考量，違反即停止）

1. **Agent 不得輸入任何密碼**——含出版社平台、ESA 校務行政系統、NotebookLM，也含「用腳本以環境變數提交登入表單」這種迂迴做法（那本質上仍是 Agent 把密碼送進表單）。登入一律由使用者本人在自己的瀏覽器完成；Agent 只能讀取既有登入狀態，或使用使用者提供的已授權深連結。
2. **Step 0、Step A、Step 1～Step 5 必須完整執行，不得自行判斷「這次應該不需要」而跳過任何一步。** 若本次所需教材已經存在，也要先核對檔案是否完整覆蓋命題範圍，再進入 Step 1。
3. **遇到不確定的狀況要暫停、跳出來讓使用者決定，不能自己猜一個答案就繼續做。** 包含但不限於：教材範圍不明確、擷取到的教材內容有缺漏或亂碼、布隆姆百分比與題型百分比加總對不上、雙向細目表某一格找不到合適的知識點可對應。
4. **所有回應與產出文件一律使用繁體中文。**
5. **題目一律由 AI 依教材內容全新撰寫**，不得直接取用出版社自帶題庫（例如康軒「新出題高手」），避免與安親班撞題。
6. **不得繞過瀏覽器的下載保護機制。** 若下載被攔截，請使用者親手補下載，不要設法規避。
7. 需要 OAuth 授權的服務（NotebookLM 等）未連接時，**詢問使用者是否要連接建立，或放棄該動作**，不能自己決定跳過或硬做。

## Step 0：命題條件設定（功能一）

用自然對話向使用者確認以下項目，缺一不可：

| 項目 | 說明 |
|------|------|
| 學年度／學期 | 例：115 上 |
| 年級 | 例：六年級 |
| 科目 | 國語／數學／社會／自然／英語 |
| 次別 | 第一次／第二次／第三次定期考察（部分學校稱「定期評量」，沿用使用者用語） |
| 出版社版本 | 康軒／翰林／南一 |
| 單元／課次範圍 | 例：第一~二單元（第 1~5 課） |
| 總分與配分規則 | 總分、題數或每題配分規則 |
| 題型與各自百分比 | 例：選擇 40、是非 20、填充 10、素養題組 30，合計 100 |
| Bloom 認知層次比例 | 例：記憶 20%、理解 30%、應用 30%、分析 10%、評鑑與創造 10%，合計 100 |

- **題型清單必須把「素養題」列為獨立類別**，不要併進選擇或問答。
- 確認百分比加總合理（題型加總 100%、布隆姆加總 100%）。需要把百分比換算成題數或配分時，**先列出換算表與餘數分配方式讓教師確認**，不要自行默默調整。

完成後在 `命題成果/<學年度><學期>_<年級>_<科目>_<次別>/設定摘要.md` 存檔（此時先建立這個子資料夾），並請使用者確認無誤才進入 Step A。

## Step A：出版社教材下載與歸檔（2026-08-04 改版流程，2026-09-04 實測結案）

入口：**新北親師生平台 `pts.ntpc.edu.tw`**（不是新北校園通）。三家出版社（康軒／翰林／南一）皆已實測可行，以 Claude in Chrome 讀取使用者真實瀏覽器的既有登入狀態。

> **分工說明**：登入這個動作本身必須由使用者完成（絕對原則第 1 點不變）。登入完成之後，換頁面／切單元／點擊下載按鈕這些屬於**操作既有登入 session**、不涉及憑證輸入的動作，由 Agent 接手執行，但每次下載後都要**實際核對檔案有落地**，不是假設點了就成功。

### 流程

1. **開始前提醒使用者**：整個 Step A（與 Step 4）期間 **Chrome 視窗不要關閉、不要讓電腦休眠**。關閉視窗會導致擴充功能連線與登入 session 全部遺失。若偵測到多個可用瀏覽器，先用該環境支援的詢問方式請使用者選擇要用哪一個再導航。
2. **Agent 導航到正確的出版社／年級／科目／單元頁面**：
   - **康軒**：用使用者提供的授權深連結（形如 `945cloud.knsh.com.tw?code=...&series=...`）建立 `*.knsh.com.tw` 網域 session，再切到 `digitalmaster.knsh.com.tw` 對應單元網址（`#year=...&field=...&grade=...&item=teach`）。若使用者沒提供過深連結，先跟使用者要。
   - **翰林**：`edisc3.hle.com.tw`（翰林行動大師 3）。**PDF 的正確入口是左側選單「教材資源／PPT」（頁面 `gwty_v2023.html`）→ 備課教材**，不是首頁「尋找資源→電子書」那一區（那區只有光碟 ISO 與 H5 線上閱讀器，都拿不到 PDF）。
   - **南一**：`nanibox3.oneclass.com.tw/resource`。
   - 深連結取得技巧：登入親師生平台後 `GET /private/myfavorites`（帶 session cookie）會回傳每個服務的 `entry_url`／`service_type`／`sso_url`。翰林為 `openid_connect` ＋ `https://moe.ntpc.edu.tw/hanlin/`，南一為 `openid_connect` ＋ `https://moe.ntpc.edu.tw/nani/`。**磁貼點不動時直接導航 `sso_url` 一樣能完成 SSO，比跟磁貼 JS 互動可靠。**
3. **若偵測到未登入（例如出現帳號密碼欄位）→ 停下來，把畫面引導到使用者眼前，請使用者本人在該畫面完成登入**。Agent 絕不代填帳密。
4. 使用者確認登入完成後，**Agent 接手**：把頁面上看到的可下載項目整理成清單告訴使用者（哪個出版社、哪個單元、檔名、頁面若有顯示檔案大小也一併列出）。純線上「免下載」的電子書閱讀器（康軒網頁版電子書、南一 OneBook、翰林 H5）標記為「僅線上瀏覽，無法下載」，改用線上閱讀擷取內容，不強求下載。
5. **若 `命題範圍三家出版商教材/` 已經有本次要用的教材檔案**，仍要先核對出版社、年級、科目、冊別、課次範圍與檔案數量是否足以覆蓋 Step 0 設定；有缺漏才進入下載。
6. **下載方式優先序**：
   - **首選：網站自己的「勾選 ＋ 下載已勾選項目」**。伺服器會打包成單一 ZIP，只觸發一次下載動作，天然避開 Chrome 的多檔封鎖（見下方陷阱）。
   - 次選：逐一點擊「單檔下載」。
7. **每點一次就比對下載資料夾**（預設 `C:\Users\<使用者>\Downloads`，或使用者指定的位置）點擊前後的檔案清單與時間戳，確認新檔案（或新 ZIP）確實落地才算該檔成功，不能只憑「點擊沒有跳出錯誤」就假設成功。
   - 確認已落地 → 可連續點擊清單上的下一個檔案，不需每一個都先問過使用者。
   - 落地失敗（被導回登入頁／被瀏覽器攔截／逾時仍無新檔）→ **停下來如實告知使用者**，請使用者親手點擊該檔案完成下載。不要重試偽裝成功，也不要靜默跳過。
8. 全部清單跑完後，把「Agent 自動下載成功」與「需要使用者親手補下載」的檔案**分開列給使用者看一次**，方便使用者知道還缺什麼。
9. 確認檔案都在下載資料夾後，Agent 把檔案搬到 `命題範圍三家出版商教材/<出版社>/<學年度><學期>_<年級>_<科目>/`（處理 ZIP 解壓縮），並產出 `教材下載清單.md` 記錄每份檔案的名稱、範圍、用途、是否誤下載。搬移前不需要再另外詢問；但若要從清單以外的其他來源下載檔案，仍要先確認檔名／來源／大小再進行。

### 已知陷阱（皆為實測踩過）

- **Claude in Chrome 要「側邊面板打開」才會建立連線**。只安裝擴充功能並授予網站權限、但沒點開面板時，`list_connected_browsers` 會一直回傳空陣列，容易誤判成「沒登入」或「沒裝擴充功能」。
- **Chrome 會靜默封鎖同一網站的第 2 個以後的自動下載**：第一個成功後，連續點擊會全部無聲失敗，下載夾無新檔也無錯誤訊息。需使用者到網站設定把「自動下載」改為允許（屬變更瀏覽器設定，**須由使用者本人操作**）。這正是「勾選＋打包 ZIP」列為首選的原因。
- **落地檔案會以 GUID `.tmp` 形式停留一段時間才更名**，其實內容已完整。驗證方式：**大小連續兩次相同 ＋ 檔頭魔數（PDF 為 `%PDF-`、檔尾 `%%EOF`）＋ `zipfile.testzip()`**。
- **ZIP 內檔名是 Big5**，需 `name.encode('cp437').decode('big5')` 還原，並移除 `(115f233421)` 之類流水號尾碼。
- **教材檔案的拆分邏輯每科不同，一律先下載目次確認，不要憑檔名猜**：
  - 翰林**社會**教師專用課本按「**單元**」拆：CH1 = 第一單元（整合該單元全部課次）、CH2 = 第二單元⋯。2026-08-04 因誤判為按課拆分，多下載了 CH3~CH5，浪費三輪往返。
  - 翰林**數學**按「**課**」拆：L01~L10 即單元一~十。不能把某一科的邏輯套到另一科。
- **窄視窗會讓 RWD 收合左側選單**。2026-09-03 曾因預覽列瀏覽器視窗太窄看不到翰林左側選單，錯誤地下了「翰林不提供 PDF」的結論。找不到某個功能時，先確認是不是選單被收起來了。
- **預覽列內建瀏覽器會吃掉 `window.open`**。需要開新視窗的流程一律走 Claude in Chrome ＋真實 Chrome，不要用預覽列硬闖。
- **若連線意外中斷，第一件事是呼叫 `list_connected_browsers`** 確認目前偵測到的裝置是否還是原本那個，不要預設連線沒變。
- 教材檔案很大（康軒六上國語課本／習作／教冊約 183MB；翰林五上數學 31 個 PDF 約 337MB），`命題範圍三家出版商教材/` 已在 `.gitignore` 排除，不進版控（著作權＋檔案過大）。

## Step 1：教材內容擷取

依 Step 0 的命題範圍，從 `命題範圍三家出版商教材/` 篩出對應課次的課本／習作／備課用書，逐頁擷取文字（圖片型 PDF 需要 OCR）。

- **範圍內每一課都要逐頁精讀**，不能只讀目錄或摘要。（2026-08-04 社會科 5 課全數逐頁精讀；國語科測試時只精讀了第一課「跑道」，其餘六課尚未完成，**正式使用國語科前必須補齊**。）
- 整理出重要字詞、句型、概念，每個知識點對應到 `定期命題參考架構/108領綱/` 的**學習內容代碼與學習表現代碼**。
- 產出 `教材內容擷取.md`，欄位：課次、頁碼、知識點、學習內容代碼、學習表現代碼、可命題角度。
- **若擷取內容有缺漏、亂碼、或無法可靠辨識，暫停並詢問使用者**，不要用猜測內容硬湊題目。

## Step 2：建立雙向細目表骨架

依 Step 0 的「題型 % × Bloom %」算出格子表（例：選擇題×記憶 3 題、選擇題×理解 5 題、素養題×應用 3 題⋯），每一格指定對應到哪一課的哪個知識點。

- 題型清單含「素養題」獨立類別。
- 每格需標明：題號、題型、配分、Bloom 層次、對應課次、對應知識點。
- **確保配置不會全部集中在同一課。**
- 檢查橫向（題型配分）與縱向（Bloom 比例）合計是否符合 Step 0 設定。**若百分比無法整除成題數或分數，先列出四捨五入與餘數分配方式**，不要自行默默調整。
- **這份骨架本身就是雙向細目表的草稿**：產出 `雙向細目表骨架草案.md`，先呈現給使用者確認配置合理，再進入 Step 3。

## Step 3：逐格撰寫題目

依骨架上每一格（題型 ＋ 認知層次 ＋ 對應知識點），參考 `定期命題參考架構/紙筆測驗的命題原則.docx` 撰寫全新題目，每題附：**正確答案、對應課次／頁碼、學習內容代碼、評量目標**。

### 素養題額外要求

額外參考 `素養導向紙筆測驗要素與範例試題(定稿版).pdf`（國語文／英語文通用原則）與 `數學素養導向評量試題研發策略.docx`（數學科專屬，非數學科略過），確保：

- **佈題強調真實且合理的情境與真實的問題**，不硬掰不合理的情境
- **扣連學習表現代碼**（不是只有學習內容代碼，**兩個都要**）
- 標註**情境範疇**（個人／社會／職業／科學，見數學素養策略文件的 PISA 四分類；或個人-環境、公共-科技等）
- 附**試題概念與分析**（說明這題想測什麼能力）
- 非選擇題形式另附**分級評分規準**

### ⚠️ 撰寫前先避開歷屆高頻命題框架（2026-09-07 新增，成本最高的一課）

**撰寫每一格之前，先問自己：這個框架是不是歷年一定會出的那一款？** 若是，換一個評量角度切入（同一個學習內容代碼，不同的問法）。

### 圖像規則與 `draw` 技能

凡題目需要學生觀察圖形、量測、判讀情境、比較實驗裝置、閱讀統計圖表、理解幾何／座標／面積／體積關係，或自然科需要看圖回答時，都要明確規劃圖像素材，**不能只留下「見圖」或空白佔位**。

1. **先看課本／習作／教師手冊有沒有現成圖示**：有就把原圖作為構圖與學科精準度的參考，可從 PDF 擷取、裁切、去除不需要的標註，再依題目文字重新標上 A/B/C、甲/乙/丙、刻度、箭頭或作答框。**不得直接照抄與題意不符的整張圖。**
2. **需要全新情境圖、示意圖、實驗圖、幾何圖、座標圖或改版教材圖時，召喚全域 `draw` 技能**，輸出到 `命題成果/<本次資料夾>/images/`：

   ```
   python <draw 技能安裝路徑>/draw.py "<圖像需求>" --name <檔名前綴> --outdir "命題成果/<學年度><學期>_<年級>_<科目>_<次別>/images"
   ```

   `draw.py` 的位置依各機器安裝而定（可能在 `~/.claude/skills/draw/`、`~/.codex/skills/draw/` 或 `~/.agents/skills/draw/`），**先確認實際存在的那一份再呼叫**，不要硬寫死路徑。預設 `--quality low`，除非使用者明確要求印刷高精度才提高品質。
   `draw` 的提示詞要包含：**題目要測的概念、需要保留或改版的課本／習作圖示特徵、圖中標籤文字、構圖比例、不可出現答案提示的限制，以及輸出需適合黑白列印或國小試卷閱讀。**
3. **高品質做法（2026-08-02 自然科實測成功）**：先從教材 PDF 提取原版高解析點陣圖 → 用 Pillow 局部擦除背景與舊字 → 以微軟正黑體重新疊加與試題文字 100% 吻合的 A/B/C 標記與 (甲)/(乙)/(丙) 答題框 → 插入 Word。兼顧原版美術水準與學科精準度。原始提取圖放 `extracted_images/`。
   （若本機無 matplotlib，統計圖／幾何圖可直接用 PIL 程式繪製，2026-09-04 五年級數學實測可行。）
4. **插入 Word 前必檢查**：圖中文字、標籤、箭頭、比例、代號是否與題幹**完全一致**。若有錯字、標示錯誤或會洩漏答案，必須重畫或改圖後才能進 Step 4。
5. **在 `試題草稿.md` 留下圖檔路徑與題號對照表**，方便 Step 5 插入 Word、後續替換與 NotebookLM 整理。
6. 若評估後判定不需要圖像（例如全用文字表格呈現素養題情境），**要在 `試題草稿.md` 寫「圖像需求評估」段落說明理由**，不要默默略過。

產出 `試題草稿.md`。

## Step 4：歷屆試題查重（呼叫 esa-exam-review）

Step 3 全部題目通過檢核清單後，把整份試題草稿（含答案）交給 `esa-exam-review`，**把這份草稿當成它原本會審查的「已上傳考卷」來源**，比對 ESA 系統上的歷屆考題。

- **覆蓋範圍：108～114 共 7 個學年度全部跑滿**，且要**逐份實際開啟比對**，不是只看清單標題。（2026-08-04 社會科是首次跑滿全 7 年。）
- **ESA 登入一樣由使用者本人完成**，Agent 只等待。操作前先確認 Chrome 側邊面板已開啟、全程不要關閉視窗。
- **不需要、也無法把歷史 PDF 存進 `光復108課綱歷年定期試題/`**。瀏覽器自動化工具有防資料外洩保護，會擋下把檔案內容以編碼文字讀出瀏覽器的動作。該資料夾維持空的是**正常狀態**，不應預先囤積歷史 PDF。
- **正確讀取方法**：用 `fetch` 在瀏覽器裡把 PDF 轉成 **blob URL**，**在頁面內嵌 iframe 顯示**（比 `window.open` 開新分頁更穩定——新分頁容易變成瀏覽器原生下載而非預覽），再用截圖＋滾動逐頁讀取內容，直接比對，不留檔案。
### 判定分級與處理原則（2026-09-07 修訂）

比對結果分四級，**處理方式不同**：

| 判定 | 定義 | 處理 |
|---|---|---|
| ★ 接近原題重複 | 題幹句式、數字或任務幾乎相同（含只換人名／情境的同一題） | **必須重寫**，無例外 |
| ▲ 命題框架高度相似 | 考點與命題框架相同，但情境／數字／問法不同 | **由命題教師決定**，並在查重報告中**逐題記錄相似處**與保留理由 |
| △ 部分相似 | 考點重疊但命題角度不同 | 保留，簡要記錄 |
| － 未發現相似 | － | 保留 |

**▲ 為什麼不一律重寫**：▲ 常是課綱核心指標的標準題型（三角形內角和求角、三角形邊長關係、範圍內找倍數），學校年年必考，**全部迴避會傷害本卷的內容效度**。正確作法是把判斷權交回命題教師，並在報告中把相似處寫清楚讓他能判斷。開始重寫前**先問使用者要改到哪一級**（★ 全改／★＋▲ 全改／★ 全改＋▲ 挑幾題），不要自行認定。

**重寫的三條硬約束**：

1. **換命題角度，不是換數字。** 只換數字或人名無法降低未來再撞的風險——本次多個框架已連續出現四到五個學年度。要改的是「這題從哪個角度切入這個學習內容」。
2. **必須守住原題型／Bloom 認知層次／單元歸屬／配分。** 做到這點，`雙向細目表.docx` 就完全不必修改（2026-09-07 實測：10 題全部重寫，細目表一個字沒動仍然正確）。這是重寫的驗收條件之一。
3. **重寫後要檢查卷內是否自我重複。** 同一單元被連改好幾題時，容易出現三、四題都在考同一個子概念，改完要通盤看一次分佈。

**重寫後必跑第二輪查重**：把改寫後的題目**再與全部 7 個學年度逐題比對一次**，並把結果列成表寫進查重報告（每題一列：改寫後題目／第二輪比對結果）。全部通過才可結案。

- 「題材相近但非同文本」不算重複，但要記錄下來提醒命題教師注意。

### ESA 操作要點（2026-09-07 實測，可省下大量摸索）

- **⚠️ 登入後只用 `fetch` 取資料，絕對不要導航到模組 JSP 網址**（`/jsp/c_exammgt/index.jsp?pid=0261`）。繞過入口框架會讓伺服器回 `index_error.jsp?err=7` 並**作廢整個 session**，必須請使用者重新登入。這是本次唯一一次中斷的原因。
- **試卷清單可一次取回整個學年期**：`POST /jsp/c_exammgt/ExamMgtAction.do`，body 帶 `method=examMain&mod=examMain&selseyear=<代碼>`（`1141`＝114學年上、`1081`＝108學年上，以此類推），不必在頁面上操作下拉選單逐年點。
- **清單是 div-based 版面**（`div.row` ＋ `div.column`，**不是** `table/tr`），解析時不能用 `querySelectorAll('tr')`。
- **PDF 檔名藏在 `no` 屬性**：試卷檔在 `div[id^=row2_itmfile_]`、解答檔在 `div[id^=row2_ansfile_]`；下載路徑為 `/central/<校代碼>/upfile/exammgt/<檔名>`（光復國小＝`014796`）。
- **部分年度的試卷檔是 `.doc`**，瀏覽器無法渲染 → **改讀解答卷 PDF**（掃描版通常含完整題目與手寫答案），一樣可以比對。
- **執行 JS 時回傳值不要含長檔名或編碼字串**，會被瀏覽器工具的防資料外洩機制擋下（回 `BLOCKED: Cookie/query string data`）。把檔名留在頁面變數內，只回傳狀態碼、檔案大小等短資訊。
- **讀 PDF 時不要點擊 PDF 內容區**（會造成 tab 凍結），只用 scroll ＋ 截圖／zoom。
- 產出 `查重報告.md`，記錄：比對範圍與方式、每個學年度取得的試卷（版本／範圍／頁數／命題者）、**四級判定總覽表**、★ 逐題重寫紀錄（原題／撞到誰／改寫後／理由）、▲ 保留題的逐題相似說明、△ 簡述、**第二輪查重結果表**，以及本次的操作方法紀錄（供未來任務參考）。

### 修改既有 .docx：優先就地編輯，不要整份重生（2026-09-07 新增）

Step 4 查重後回頭改題、或功能五替換題目時，**用 python-docx 就地編輯既有 `.docx`**，不要重跑產生腳本整份重做——重生會遺失已套用的範本格式與手動微調。

- **改文字**：找到目標段落，保留第一個 run 當格式範本、刪掉其餘 run，再寫入新文字；需要換行時用 `run.add_break()` ＋ `run.add_text()`，不要新增段落（避免破壞行距）。

- 動檔案前先複製一份 `<原檔名>_Step4前備份.docx`，確認新版無誤再由使用者決定是否刪除。

### 技術防呆（血淚教訓）

- **⚠️ Node.js 組合含中文字元的檔案路徑，一律用 `path.join()` 或等價路徑 API，絕對不要用字串相加＋反斜線。** 2026-08-02 因 `OUT_DIR + '\測試試題卷.docx'` 少打一個反斜線，JavaScript 把無法識別的跳脫字元 `\測` 直接吃掉反斜線，路徑少了分隔符號，檔案寫到錯誤位置，**且不會拋出任何例外**，一度誤判為 Word 檔案鎖定或 GDrive 同步問題，排查耗時極久，還在專案根目錄留下亂碼垃圾檔。
- 使用 `docx` npm 套件產出 Word。
- **輸出後要檢查目標資料夾中的檔案時間與大小**，必要時重新開檔或讀取文件內容，確認真的寫到正確位置。

### 輸出後 QA（必做）

**結構性 QA**（無 LibreOffice／pandoc 時的替代方案，2026-08-04 驗證可行）：用 `unzip` 取出 `word/document.xml` 再 `grep` 比對——

- 學生卷的空白括號數量 = 選擇題數 + 是非題數，且**不含任何答案**
- 教師卷的答案數量 = 各題型題數（是非題另檢查 ○/× 的分布是否合理）
- 雙向細目表的表格數量正確
- XML 內**無 `????` 亂碼**（中文編碼問題）

**視覺渲染 QA**：把三份 docx 轉成 PDF、逐頁渲染成圖檢查排版（標題、表格、題號、選項編號、圖片位置、中文有無缺字或跑版）。

先確認本機有沒有 LibreOffice：

```bash
# Windows 常見位置
ls "/c/Program Files/LibreOffice/program/soffice.com"
```

有的話用 headless 轉檔（2026-09-04 於 DESKTOP-31QBU95 實測通過，LibreOffice 26.8.0.3）：

```bash
"/c/Program Files/LibreOffice/program/soffice.com" --headless --norestore --convert-to pdf --outdir "<輸出目錄>" "<來源.docx>"
```

再用 PyMuPDF 驗證並渲染成圖檢視：

```python
import fitz
d = fitz.open('<轉出的.pdf>')
print(d.page_count, len(d[0].get_text()))
d[0].get_pixmap(dpi=110).save('page1.png')
```

**兩個實測踩到的陷阱**：

- **必須用 `soffice.com`，不能用 `soffice.exe`**。`.exe` 會立刻脫離回傳（0 秒、完全沒有輸出檔），看起來像失敗其實根本沒等它做完；`.com` 才會同步等待轉檔完成（一份 5 頁試卷約 12 秒）。
- **不要用 exit code 判斷成敗**。`.com` 實測回傳 `exit=1` 但 PDF 其實已完整產出。判定成功的依據是**輸出檔存在 ＋ 頁數正確 ＋ 抽得到文字 ＋ 渲染圖目視無誤**，不是 return code。

另注意 LibreOffice 的字型替換與 Word 不完全相同，渲染結果是**排版正確性的近似檢查**（足以抓出跑版、缺字、表格爆框、圖片錯位），不等於 Word 的最終呈現，仍建議命題教師實際用 Word 開一次。

**若本機確實沒有 LibreOffice**（pandoc 不在這條管線上，無法替代 docx→PDF 排版檢查），**要在 `設定摘要.md` 明確標註視覺渲染 QA 未完成**，並請命題教師實際用 Word 開啟檢查排版。**不要假裝做過。**

## 功能五：題目篩選與替換

Step 5 輸出後，教師用對話指定題號（例如「第 5、第 8 題我不要，幫我換掉」「第 3 題的 (1) 子題重出」）：

1. 讀出該格在雙向細目表中的原規格：**題型 ＋ Bloom 認知層次 ＋ 對應課次／知識點**
2. 依原規格重新出題（一樣要過試題檢核清單）
3. 跑一次 Step 4 查重
4. 通過後**直接替換進同一份 Word 試題卷與雙向細目表，不動其他任何題目的配置**

不支援整批調整（例如整課換題）。若教師要大幅改配分或範圍，回到 Step 0 整份重跑一次。

## 功能六：命題成果整理進 NotebookLM

命題流程（含篩選替換）全部確定後，詢問使用者是否要把這次成果整理進 NotebookLM 筆記本。

- 先確認連接狀態（`mcp__notebooklm-mcp__server_info` 的 `auth_status`）。若不是 `configured`，告知使用者需要自己執行 `nlm login` 完成 Google 帳號授權（**Agent 不能代為完成**），並詢問要先去登入再繼續，還是放棄這個步驟。
- **每一次命題任務都建立單獨的新 NotebookLM 筆記本**，絕不與其他學年度、年級、科目或次別混用，也不沿用舊的共用筆記本。
- 筆記本名稱格式：`<學年度><學期>_<年級>_<科目>_<次別>_命題成果`。若同名已存在，**加上日期時間**（例如 `20260802-1530`）避免沿用舊本。
- 加入該筆記本的來源：本次下載的教材 PDF、正式試題卷、教師解答卷、雙向細目表、查重報告、設定摘要／試題草稿，**再加上通用參考資料**（`定期命題參考架構/` 中本次科目需要的 Bloom 分類、命題原則、108 領綱、素養導向文件、雙向細目表範本），讓每本筆記本都能獨立使用。不必為了避免重複而省略。
- 來源已用獨立筆記本隔離時，原則上不需要再建立次別標籤；若環境或使用者要求使用標籤，只在該新筆記本內使用，不跨任務共用。
- **⚠️ 避免不必要呼叫 `label(action=list)`**——實測發現它會觸發 NotebookLM 自己的 AI 自動分類副作用，把未分類或通用來源歸到意外標籤，且目前沒有可靠的「從標籤移除」操作可以修正。

## 環境需求（跨機器踩過的坑）

- **LibreOffice**：Step 5 的**視覺渲染 QA** 需要它把 `.docx` 轉 PDF／PNG 做排版確認。截至 2026-09-07，DESKTOP-31QBU95、kfes、DESKTOP-HJA3024 **三台都沒裝**，導致連續三次任務都只能做結構性 QA。**建議在常用命題電腦安裝**，否則每次都要在 `設定摘要.md` 標註「視覺渲染 QA 未完成」並請命題教師自行用 Word 開啟確認排版。
- **python-docx**：Step 5 產出與就地編輯的主力，必備。
- **PIL／Pillow**：圖像裁切、疊字與程式繪圖（統計圖、幾何圖）用；**matplotlib 非必要**，PIL 已足夠。
- **Claude in Chrome 擴充功能**：Step A 與 Step 4 需要；注意**要把側邊面板打開才會建立連線**，只安裝不開面板會讓 `list_connected_browsers` 回傳空陣列。
