# 定期考察命題技能（exam-composer）

> 本檔於 2026-09-03 依專案 repo 的 `agents.md`（功能設計總覽＋測試發現與修正 11 點）與 `README.md` 重建。原始版本（SHA-256 `E44025BE…FD0F43`，2026-08-04 Step A 改版版）僅存於 DESKTOP-31QBU95，未進版控。**若日後取回原版，請以原版為準並比對差異。**

## 適用對象與定位

- 使用者：新北市中和區光復國小校長，技能的實際使用對象是校內命題教師。
- 定位：**生成端**。負責從設定範圍到產出可審查的成果。
- 分工：審查端（歷屆試題查重與審查）由 `esa-exam-review` 負責（位於 `~/.codex/skills/esa-exam-review` 與 Claude Code 外掛 `anthropic-skills:esa-exam-review`），兩者不重疊。Step 4 會呼叫它。
- 專案目錄：`G:\我的雲端硬碟\AI作品\定期考察命題技能`（GitHub：hsuyiping-rgb/exam-composer-skill）。

## 絕對原則（違反即停止）

1. **Agent 不得輸入任何密碼**——含出版社平台、ESA 校務行政系統、NotebookLM，也含「用腳本以環境變數提交登入表單」這種迂迴做法。登入一律由使用者本人在自己的瀏覽器完成，Agent 只能讀取既有登入狀態或使用使用者提供的已授權深連結。
2. **Step 0～Step 5 必須完整執行，不得自行判斷跳過任何一步**。遇到不確定的狀況要**暫停詢問使用者**，不能自己猜答案繼續做。
3. **所有回應與產出文件一律使用繁體中文**。
4. **題目一律由 AI 依教材內容全新撰寫**，不得直接取用出版社自帶題庫（例如康軒「新出題高手」），避免與安親班撞題。
5. **不得繞過瀏覽器的下載保護機制**。若下載被攔截，請使用者親手補下載，不要設法規避。
6. 需要 OAuth 授權的服務（NotebookLM 等）未連接時，**詢問使用者是否要連接建立，或放棄該動作**，不能自己決定跳過或硬做。

## Step A：出版社教材下載與歸檔（2026-08-04 改版流程）

入口：**新北親師生平台 `pts.ntpc.edu.tw`**（不是新北校園通）。三家出版社（康軒／翰林／南一）皆已實測可行，以 Claude in Chrome 讀取使用者真實瀏覽器的既有登入狀態。

### 流程

1. **開始前提醒使用者**：整個 Step A（與 Step 4）期間 **Chrome 視窗不要關閉、不要讓電腦休眠**。關閉視窗會導致擴充功能連線與登入 session 全部遺失。
2. Agent 導航到正確的出版社／年級／科目／單元頁面。
3. **若偵測到未登入 → 停下來，請使用者本人在畫面上完成登入**。Agent 絕不代填帳密。
4. 使用者確認登入完成後，**Agent 接手**：整理本次範圍所需的檔案清單，逐一點擊「單檔下載」。
5. **每點一次就比對下載資料夾**，確認有新檔案真的落地才算該檔成功。
6. 落地失敗（被導回登入頁／被瀏覽器攔截／無新檔）→ 請使用者親手補下載該檔案，不要重試繞過。
7. 全部取得後，Agent 把檔案搬到 `命題範圍三家出版商教材/<出版社>/<學年度><學期>_<年級>_<科目>/`，並產出 `教材下載清單.md` 記錄每份檔案的名稱、範圍、用途、是否誤下載。

### 已知陷阱

- **⚠️ 此新流程尚未經過真實端到端驗證。** 2026-08-04 的社會科任務仍是用舊流程（使用者全程親手點擊）跑完的，SKILL.md 是任務結束後才改的。**下次執行 Step A 就是首次實測**：務必留意康軒／翰林／南一的下載按鈕在 Agent 點擊後是否真的觸發瀏覽器下載，還是被導向登入頁或被攔截，並把結果（成功／被導登入頁／被攔截）記錄回專案 `agents.md`「測試發現與修正」第 10 點。
- **翰林「教師專用課本」PDF 是按「單元」拆分，不是按「課」**：CH1 = 第一單元（整合該單元全部課次）、CH2 = 第二單元、CH3 = 第三單元⋯以此類推。**不要看到範圍有多個課次就假設每課各一檔**。下載前先開檔案第一頁確認實際涵蓋範圍。2026-08-04 因誤判多下載了 CH3~CH5，浪費三輪往返。
- 純線上「免下載」電子書不強求下載，改用線上閱讀擷取內容。
- 若連線意外中斷，**第一件事是呼叫 `list_connected_browsers` 確認目前偵測到的裝置是否還是原本那個**，不要預設連線沒變。
- 教材檔案很大（康軒六上國語課本／習作／教冊約 183MB），`命題範圍三家出版商教材/` 已在 `.gitignore` 排除，不進版控（著作權＋檔案過大）。

## Step 2：建立雙向細目表骨架

依「題型 % × Bloom %」建格子表，每一格對應到具體課次與知識點。

- 題型清單含「素養題」獨立類別。
- 每格需標明：題號、題型、配分、Bloom 層次、對應課次、對應知識點。
- 檢查橫向（題型配分）與縱向（Bloom 比例）合計是否符合 Step 0 設定，不符就調整格子分配。
- 產出 `雙向細目表骨架草案.md`，請使用者確認後才逐格出題。

## Step 3：逐格撰寫題目

依骨架逐格撰寫全新題目，每題附：**答案、對應課次、學習內容代碼、評量目標**。

### 素養題額外要求

- 標註**情境範疇**（個人／社會／職業／科學，見數學素養策略文件的 PISA 四分類）
- 標註**學習表現代碼**
- 附**試題概念與分析**
- 非選擇題另附**評分規準**
- 依國教院文件的兩大要素撰寫：**真實情境佈題** ＋ **扣連學習表現／學習內容／核心素養**

### 試題檢核清單（每題寫完先過，通過才進下一格）

1. 情境真實性——情境是否合理、貼近學生生活經驗
2. 語句通順——無語病、無歧義
3. 資訊完整——作答所需資訊都在題目裡
4. 問題明確——問的是什麼一目了然
5. 公平無偏見——無性別／族群／城鄉／社經地位偏見

### 圖像規則

若題目文字需要圖像輔助（看圖回答、量測、實驗裝置、幾何圖、座標圖、統計圖、自然科圖示等）：

1. **先看課本／習作／教師手冊有沒有現成圖示**，有就作為構圖與學科精準度的參考，可裁切、改標。
2. 若需要全新情境圖、示意圖或改版教材圖，**召喚全域 `draw` 技能**產生或改版，輸出到 `命題成果/<本次資料夾>/images/`。
3. **高品質做法（2026-08-02 自然科實測成功）**：先從教材 PDF 提取原版高解析點陣圖 → 用 Pillow 局部擦除背景與舊字 → 以微軟正黑體重新疊加與試題文字 100% 吻合的 A/B/C 標記與 (甲)/(乙)/(丙) 答題框 → 插入 Word。兼顧原版美術水準與學科精準度。原始提取圖放 `extracted_images/`。
4. **插入 Word 前必檢查**：圖中文字、標籤、比例、代號是否與題幹完全一致。
5. 若評估後判定不需要圖像（例如全用文字表格呈現素養題情境），**要在 `試題草稿.md` 寫「圖像需求評估」段落說明理由**，不要默默略過。

產出 `試題草稿.md`。

## Step 4：歷屆試題查重（呼叫 esa-exam-review）

把整份草稿送 `esa-exam-review` 比對 ESA 系統上的歷屆考題。

- **覆蓋範圍：108～114 共 7 個學年度全部跑滿**，且要**逐份實際開啟比對**，不是只看清單標題。（2026-08-04 社會科是首次跑滿全 7 年。）
- **不需要、也無法把歷史 PDF 存進 `光復108課綱歷年定期試題/`**。瀏覽器自動化工具有防資料外洩保護，會擋下把檔案內容以編碼文字讀出瀏覽器的動作。該資料夾維持空的是**正常狀態**。
- **正確讀取方法**：用 `fetch` 在瀏覽器裡把 PDF 轉成 **blob URL**，**在頁面內嵌 iframe 顯示**（比 `window.open` 開新分頁更穩定——新分頁容易變成瀏覽器原生下載而非預覽），再用截圖＋滾動逐頁讀取內容，直接比對，不留檔案。
- **ESA 登入一樣由使用者本人完成**，Agent 只等待。
- 比對結果分三類：完全相同 / 命題框架相近 / 未發現相同題。前兩類**只重寫該格**（維持原題型＋Bloom 層次＋對應課次），重寫後再送查重，直到全過。
- 「題材相近但非同文本」不算重複，但要記錄下來提醒命題教師注意。
- 產出 `查重報告.md`，記錄每個學年度比對了幾份、發現什麼、哪幾題改寫、怎麼改。

## Step 5：格式化輸出

產出三份 Word 檔到 `命題成果/<本次資料夾>/`：

1. `正式試題卷.docx`——學生卷，**不得含答案**
2. `教師解答卷.docx`——含全部答案與素養題參考答案／評分規準
3. `雙向細目表.docx`——**套用 `定期命題參考架構/新北市中和區光復國小定期評量雙向細目分析表.docx` 的格式**

### 技術防呆（血淚教訓）

- **⚠️ Node.js 組合含中文字元的檔案路徑，一律用 `path.join()`，絕對不要用字串相加＋反斜線。** 2026-08-02 因 `OUT_DIR + '\測試試題卷.docx'` 少打一個反斜線，JavaScript 把無法識別的跳脫字元 `\測` 直接吃掉反斜線，路徑少了分隔符號，檔案寫到錯誤位置，**且不會拋出任何例外**，一度誤判為 Word 檔案鎖定或 GDrive 同步問題，排查耗時極久，還在專案根目錄留下亂碼垃圾檔。
- 使用 `docx` npm 套件產出 Word。

### 輸出後 QA（必做）

**結構性 QA**（無 LibreOffice/pandoc 時的替代方案，2026-08-04 驗證可行）：
用 `unzip` 取出 `word/document.xml` 再 `grep` 比對：
- 學生卷的空白括號數量 = 選擇題數 + 是非題數，且**不含任何答案**
- 教師卷的答案數量 = 各題型題數（是非題另檢查 ○/× 的分布是否合理）
- 雙向細目表的表格數量正確
- XML 內**無 `????` 亂碼**（中文編碼問題）

**視覺渲染 QA**：若本機無 LibreOffice／pandoc 無法轉 PDF 確認排版，**要在 `設定摘要.md` 明確標註此限制**，並建議命題教師實際用 Word 開啟檢查排版。不要假裝做過。

## 功能五：題目篩選與替換

使用者用對話指定題號（例如「換第 12 題」「第 3 題的 (1) 子題重出」）：

1. 讀出該格在雙向細目表中的原規格：**題型 ＋ Bloom 認知層次 ＋ 對應課次／知識點**
2. 依原規格重新出題（一樣要過試題檢核清單）
3. 跑一次 Step 4 查重
4. 通過後**直接替換進同一份文件，不動其他任何配置**

不支援整批調整。若使用者要大幅改配分或範圍，回到 Step 0 重來。

## 功能六：命題成果整理進 NotebookLM

命題流程完成後執行。

- **每一次命題任務都建立單獨的新 NotebookLM 筆記本**，絕不與其他學年度、年級、科目或次別混用，也不沿用舊的共用筆記本。
- 筆記本名稱格式：`<學年度><學期>_<年級>_<科目>_<次別>_命題成果`。若同名已存在，**加上日期時間避免沿用舊本**。
- 加入該筆記本的來源：本次教材 PDF、正式試題卷、教師解答卷、雙向細目表、查重報告，**加上通用參考資料**（Bloom 分類、命題原則、108 領綱、素養導向文件、雙向細目表範本），讓每本筆記本都能獨立使用。
- **⚠️ 避免呼叫 `label list`**——它會觸發 NotebookLM 自己的 AI 自動分類副作用，且沒有可靠的「從標籤移除」操作。因任務已用獨立筆記本隔離，原則上不需要跨任務標籤。
- 若使用者的 NotebookLM 未連接／未登入，**詢問使用者是否要連接建立，或放棄這個動作**，不能自己決定跳過或硬做。
